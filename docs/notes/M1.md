# M1：协议、模拟器与测试

本阶段让一台电脑同时扮演泵站和上位机。Simulator 是“设备”，ConsoleDemo 是“读取设备的人”，Core 是双方理解的报文规则。这样先把通信与报警逻辑学清楚，后续加界面时只需要使用已有接口。

## 关键代码与设计原因

- `Core/Protocol/ModbusFrames.cs`：先制作功能码和参数，再封装为 TCP 或 RTU。分开是因为两者的数据含义相同，但外层校验不同。
- `Core/Protocol/ModbusClientBase.cs`：一个客户端每次只执行一组请求/响应，减少串包；读失败退避重试，写失败保留结果未知。
- `Core/Protocol/ModbusTcpClient.cs`：ReadExactlyAsync 解决分包，MBAP 长度确定读取范围。
- `Core/Protocol/ModbusRtuClient.cs`：端口打开放在线程池；收发使用异步流；取消时关串口，防止驱动忽略取消令牌。
- `Simulator/StationState.cs`：四设备用数值模型产生数据，所有修改在同一锁内，故障注入和网络请求不会读到半更新状态。
- `Core/Alarms/AlarmEngine.cs`：不依赖 UI、数据库和系统时间，输入一次采样，输出零到多个状态变更，因此延时测试无需真实等待。

以上 Core/Simulator 分别指 src 下的同名完整项目目录。

## 验收

Release 构建无警告无错误；42 项 xUnit 测试通过；两个独立进程完成真实 TCP 单写、批量写、读保持寄存器、读输入寄存器、读离散输入和线圈控制。原始记录在 `docs/evidence/`。

RTU 编码、CRC 和解析已测试，物理串口与虚拟串口链路未运行。没有把该项写成通过。当前采用 .NET 10，未验收 Visual Studio 2022 构建。
