# 运行手册

## 启动与数据目录

推荐双击根目录 `Start-Demo.cmd`，或分别运行：

```powershell
dotnet run --project src/PumpStationMonitor.Simulator -c Release -- 1502
dotnet run --project src/PumpStationMonitor.App -c Release
```

登录管理员 `admin / Admin123!`，或操作员 `operator / Operator123!`。默认账号用于本地演示，可在系统设置修改密码。密码使用随机盐 PBKDF2-SHA256，210,000 次迭代，数据库不存明文。连续五次失败会等待 30 秒再允许登录。

默认数据目录 `%LOCALAPPDATA%/PumpStationMonitor/`：`station.db` 为业务数据库，`logs/station-日期.log` 为日志。可通过环境变量 `PUMP_DATA_DIR` 指定隔离目录；自动验收使用独立目录，不修改演示数据。不要同时启动多个 App 连接同一个数据库。

`App/appsettings.json` 提供首次建库默认参数；之后系统设置保存到 `comm_settings`，数据库优先。保存后自动重建客户端并重连。串口使用 9600/8/E/1；切换 RTU 前需准备真实或虚拟从站，内置模拟器只支持 TCP。

## 页面操作

- **站点总览**：状态灯、频率/液位/压力、比例条、关键值。管理员可用 Coil（05）或 Register（06）启停水泵；操作员按钮禁用，服务层也拒绝越权。超时不自动重发写入，结果未知时先回读。
- **实时数据**：设备、名称、值、单位、质量、更新时间、功能码/地址/位。坏质量和过期数据显示破折号，保留更新时间；不能把通信失败理解成设备正常。
- **运行趋势**：任选点位，1/5/15/60 分钟窗口。每点最多缓存 60 分钟，显示最多约 1,500 点，无效值断线。程序重启后使用历史页查询已入库数据。
- **报警中心**：活动报警自动刷新；选行确认。历史支持时间查询、确认已经恢复但未确认的记录、CSV 导出。确认不代表恢复，HH/H/L/LL 为独立规则，可能同时报警。
- **历史查询**：设备/点位/起止时间筛选，最多 10,000 条，表格与图形。播放按钮推进回放，暂停或拖动进度条定位。图形最多约 2,000 点。
- **系统设置**：通信、点位增删改、报警规则、账号管理、保留天数。选行后编辑；现有点位和规则的标识只读，新增时填写新标识。活动报警关联的点位/规则先恢复再修改，防止失去报警追踪。删除点位仍保留历史。

时间统一在数据库存 UTC Unix 毫秒，界面和查询输入按本机当地时间。输入格式 `yyyy-MM-dd HH:mm:ss`。查询结果达到上限时缩小时间范围。

## 默认点表

地址全部零基，不能直接输入 40001 这类展示地址。

| 设备 | 寄存器 | 含义 | 换算 |
|---|---|---|---|
| 1# 泵 | 0 | bit0 运行、bit1 故障、bit2 远程、bit3 自动 | 位解析 |
| 1# 泵 | 1 / 2 / 3 | 电流 / 频率 / 累计运行 | ×0.1 A / ×0.1 Hz / h |
| 2# 泵 | 10 / 11 / 12 / 13 | 同上 | 同上 |
| 集水池 | 20 / 21 / 22 | 液位 / 进水流量 / 高低开关 | ×0.01 m / ×0.1 m³/h / bit0 高、bit1 低 |
| 出水管路 | 30 / 31 / 32 | 压力 / 流量 / 阀门 | ×0.001 MPa / ×0.1 m³/h / ×0.1 % |
| 控制 | 40 / 41 | 单寄存器 0 停、非 0 启动 | 06 |
| 演示区 | 100～127 | 自由读写 | 原始值 |

保持寄存器用 03，输入寄存器用 04（每 200 ms 镜像）。线圈 0/1 用 01/05 读写两泵启停；离散输入 0/1 是故障，2/3 是高低液位。模拟器每类区域 128 项，越界返回异常码 02。累计运行初值 100 h，之后只累计运行时长，重启模型重置。

新增点位支持 UInt16、Int16、Float32；浮点使用两个寄存器，字节序 Abcd/Badc/Cdab/Dcba。位点与 Float32 不能混用。采集按设备、功能码分组，相邻地址合并，默认 23 点每轮 6 次请求。

## 报警与持久化

位报警非零触发；H/HH 大于等于阈值，L/LL 小于等于阈值；持续达到延时才产生。高报警恢复需低于“阈值−死区”，低报警恢复需高于“阈值+死区”。坏质量重置待触发延时，但不将活动报警恢复。恢复和确认时间分开保存，重启加载活动发生 ID，避免把同一持续故障重复产生。

历史使用有界 Channel，200 条或 1 秒提交事务，队列满则异步等待形成背压。正常退出先停采集，再排空队列。每小时按保留天数分块清理 history，报警记录保留。SQLite WAL 和参数化 SQL 支持边采集边查历史。SQLite 驱动自身并非真正异步磁盘 I/O，后台任务承担采集与写库，文档不将驱动包装等同于异步引擎。

## 模拟故障

`fault 1` / `fault 2` 置泵故障并停止运行状态；`level 9.5` 锁定液位；`offline` 保持 TCP 但不响应请求；`recover` 恢复通信、故障与自然液位，保留启停命令。输入命令后最迟一个模型周期更新。`quit` 退出模拟器。

## 验收与发布

`scripts/Verify.ps1` 执行锁定还原、构建、测试和默认 10 分钟宿主运行。`scripts/Publish.ps1` 输出独立 Windows x64 运行目录。`scripts/run_ui_validation.py smoke` 使用发布版正常登录，保存六页面、设置子页、操作员禁用状态截图；需 Python。`endurance` 则让真实窗口趋势页运行两小时，写出 CPU/内存/轮询 CSV。

原始证据在 `docs/evidence`，长测运行目录在 `artifacts`。当前 RTU 链路未实测；不能将 CRC 测试视作串口驱动兼容性验收。
